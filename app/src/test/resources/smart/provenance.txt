Smart JSON fixture provenance

These JSON files are generated by the production sing-box Smart APIs, not maintained as handwritten protocol samples.

Core sources:
- protocol/group/smart_api.go: SmartStatus, SmartNetworks, SmartExport, SmartImport, smartExportDocument, smartImportReport.
- protocol/group/smart_test.go: smartTestGroup, using the fixed Unix timestamp 1800000000 and members a/b.
- protocol/group/smart_history.go: smartHistory.Observe, smartEvent, smartExportStatistic.
- protocol/group/smart_ledger.go: smartBudget and smartLedger.Snapshot.

Generator: app/src/test/fixtures/smart_fixture_test.go in the Android repository. Copy it to protocol/group/smart_android_fixture_test.go in sing-box-extended, then run from that checkout (set ANDROID_ROOT to the Android repository):

SMART_ANDROID_FIXTURES="$ANDROID_ROOT/app/src/test/resources/smart" go test -tags=with_gvisor,with_quic,with_dhcp,with_wireguard,with_utls,with_acme,with_clash_api,with_tailscale,with_ccm,with_ocm,badlinkname,tfogo_checklinkname0 ./protocol/group -run '^TestAndroidSmartFixtures$' -count=1

Remove the temporary core test after generation; retain the emitted JSON files with these Android tests.

Fixture scenario:
- A healthy primary a and standby b on cell/25001/LTE, carrier Fixture Carrier, country RU; primary country NL.
- Selection generation 9, direct RTT 42 ms, one successful 120 ms history observation, an active 48.1/12.5 Mbps measurement, and a network_change event.
- UDP/443 fails on a and succeeds on b, which remains in the same tier.
- Core emits all 96 timeline triples, including null triples for unobserved intervals.
- Redacted export leaves model/android/app empty, as the current core does.
- Import uses the production export with a foreign source install ID plus foreign-redacted-key and unknown-member records. A second import produces the replacement report.
- A fresh group with no selected members produces the starting status and empty network list. Import with no running Smart groups produces an empty report.

Tests derive missing, blank, and unsupported-version variants by modifying these core-generated documents with kotlinx.serialization JSON objects.
